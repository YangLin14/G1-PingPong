# G1 反手側下旋發球（暫緩）

狀態：**擱置**（2026-10-10）。優先改做正手對打。本文件保留完整計畫，之後可直接接手。
分支：`serve-side-backspin`（從 `triton-droids/HOPE` 的 `g1-port` 分出）。

## 1. 任務定義

Unitree G1（29 DoF，右手持拍）站在己方端線後：

1. 左手托球，**放球**（不拋球；ITTF 2.6.2 要求近乎垂直上拋 ≥ 16 cm，比賽不合法，之後再升級）。
2. 球下落時，右手**反手**揮拍，路徑在俯視圖中由**左下往右上**（由內往外、往前、往上撈）。
3. 觸球點：俯視為球的**後側偏右**，從後方看為球的**下半部**；拍面打開（朝上偏左前）。
4. 出球：**下旋約 20 轉/秒（≈ 126 rad/s）** + 側旋；合法發球（己方台面一跳 → 過網 → 對方台面一跳）。
5. 一致性：在放球位置與時間誤差下，旋轉與落點的變異要小。

### 物理檢查（x 朝網、y 朝左、z 朝上）

- 觸球點 r ∝ (−後, −右, −下)，拍子速度 v ∝ (+前, −右, +上)。
- 摩擦力矩 r × F 給出：ω_y < 0（下旋）、ω_z > 0（俯視逆時針側旋）、少量 ω_x（側拐）。
- 空中 Magnus 力讓球**往發球者左邊**偏。
- 注意：拍子若只做水平移動又去碰「右下」，拍面法向分量為負（拍子離開球）。**必須有往前、往上的分量**才壓得到球。

## 3. 現有可重用的東西（HOPE / g1-port）

- `configs/ball_physics_venue.yaml`：**已有旋轉模型**。飛行 `a = g − k_d|v|v + k_m(ω×v)`，以及飽和升力式 `C_L(SR)`；拍子接觸是切向衝量產生旋轉的模型，`e(u_n)` 隨法向速度改變；桌面也有咬球參數。
  - 驗證範圍：球速 1–7 m/s、**旋轉 0–15 rev/s**、SR ≤ 0.5。20 rev/s 屬外推。
  - 參數是用 3.4 g 鍍膜比賽球擬合的；一般 2.7 g 球改用 `k_d_clean_scaled = 0.1588`、`k_m_clean_scaled = 0.00559`。
- `tasks/tracking/mdp/virtual_ball.py`：上述模型的 torch 批次版，含 `predict_paddle_contact` 與 `rk4_step`。
- `apps/a3_mujoco_serve/`：A3 的確定性發球 pipeline（網格搜尋擊球 → DLS IK → 關節 CSV → 重播驗證）。目前不考慮旋轉，但流程可直接借用。
- g1-port：G1 的 URDF/MJCF（右手掌固定球拍）、Isaac 訓練框架（BeyondMimic 追蹤 + PPO）、MuJoCo sim-to-sim、Isaac 與 MuJoCo 的物理比對檢查。

## 4. 技術路線

### 第 1 步：考慮旋轉的發球模擬器 + 擊球參數搜尋（不需要機器人）

- `scripts/serve_search.py`（torch 批次，Mac 或叢集都能跑）：
  - 放球：從左手位置靜止釋放，位置與時間加隨機誤差。
  - 擊球：`predict_paddle_contact` 搭配 venue 參數，Magnus 改用飽和式，用 clean-ball 係數。
  - 飛行：RK4，h = 2 ms。
  - 桌面反彈：同一個接觸模型，`v_r = 0`、`n = +z`，桌面參數 `e = 0.9215`、`a_t = 0.369`、`μ = 2.0`。
  - 合法性：己方一跳 → 過網高度 ≥ 網高 + R → 對方一跳。另外檢查擊球時球在台面上方、端線後方。
- 搜尋變數：觸球時間、觸球位置偏移（±7 cm）、拍子速度（3 維）、拍面法向（2 個角度）。
- 獎勵（照 Ace 的做法）：先算合法性扣分，合法後再看以下項目：
  - 擊球後下旋與 −126 rad/s 的差距；
  - 側旋 > 0（大小可設定，先以 0.5 倍下旋為目標）；
  - 觸球點必須落在「後、右、下」八分之一區；
  - 落點、球高；
  - 在放球誤差下的變異。
- 最佳化方法：先隨機搜尋，再用 CMA-ES 或 HEBO。
- 產出：前幾名的擊球參數，以及每一跳的旋轉報告。
- 要檢查的風險：接觸模型的 `mu_safety = 0.5` 會限制切向衝量。達到 126 rad/s 需要 |Δv_t| ≈ 1.7 m/s，也就是切向速度約 3.2 m/s、法向速度 ≥ 2 m/s，**可能被上限卡住**。如果被卡，要回頭查文獻或實測膠皮的切向參數。

### 第 2 步：G1 參考動作（合成示範）

- 把搜尋出的擊球參數轉成 G1 右手的完整軌跡：準備 → 加速 → 觸球 → 收拍 → 回位，用 minimum-jerk 或五次多項式。
- 用 DLS IK 算出 G1 右手 7 個關節的角度（參考 `a3_mujoco_serve` 和 `retarget_a3_clip_to_g1_ik.py`），檢查關節速度和力矩上限。
  - 腕關節 pitch/yaw 只有 5 N·m，反手手腕發力可能不夠。
- 左手：托球 → 放球的姿勢。
  - 硬體注意：G1 的手是橡膠拳頭，左手需要加一塊平板托球。
- 在 MuJoCo 重播，用旋轉模型驗證觸球、旋轉和落點。
- 輸出成 HOPE 的動作格式（`.npz` + sidecar yaml），就是一段只有發球的動作 clip。

### 第 2b 步：手機錄影示範（可選，用來讓動作更自然）

- 拍攝：側面和斜後方各一支，**慢動作 120 或 240 fps**，固定機位，畫面要拍到整個人和球拍；每支 20–50 次發球。
- 影片 → 人體動作：用 GVHMR、WHAM 或 4DHumans 產生 SMPL 動作 → 用 GMR 重定向到 G1。
- 限制：手機影片很難準確重建拍面角度和旋轉，所以只用來取「身體和手臂的風格」。擊球瞬間的拍子狀態還是以第 1 步的搜尋結果為準：用 IK 修正手腕，或在強化學習時用獎勵覆蓋。
- 可以用 [Uplifting Table Tennis](https://arxiv.org/pdf/2511.20250) 的方法從 2D 球軌跡估計旋轉，量一下真人示範的轉速做參考。

### 第 3 步：強化學習（Isaac，固定骨盆）

- 新增 Isaac 任務 `HOPEServeUnitreeG1`：
  - 只用一段發球 clip；固定站位；**骨盆先固定**，平衡留到下一階段。
  - 球用運動學方式從左手釋放（加隨機誤差），擊球用 `virtual_ball` 的解析接觸模型，之後的飛行也用解析模型。
- 獎勵：
  - 追蹤參考動作；
  - 觸球位置、拍面法向、拍子速度與目標的誤差；
  - 擊球後的旋轉向量誤差；
  - 觸球點八分之一區檢查；
  - 合法性、落點、過網高度；
  - 加上平滑項。
- 觀測：本體感知、相位時鐘、球的位置和速度（放球後）。
- 評估：在 Isaac 裡用 N 次隨機放球，統計旋轉的平均值和標準差、合法率、落點分佈。

### 第 4 步：MuJoCo sim-to-sim

- 擴充 `mujoco_eval_onnx.py` 加一個發球模式：真實放球 → 用 venue 旋轉模型計算擊球和飛行 → 輸出逐球的旋轉、合法性和影片。

### 第 5 步（之後）：平衡 → 放開骨盆，改成全身控制

- 把骨盆放開，加上 g1-port 的平衡相關 reward 與終止條件。

## 5. 驗收標準

| 項目 | 目標 |
|---|---|
| 合法率（模擬，含放球誤差） | ≥ 90 % |
| 擊球後下旋 | −126 ± 20 rad/s |
| 側旋 | > 0，標準差 < 30 rad/s |
| 第二跳落點 | 對方台面，半徑 30 cm 內 |
| sim-to-sim | MuJoCo 與 Isaac 的旋轉差 < 20 % |

## 6. 待決定 / 風險

- 20 rev/s 超出 venue 模型的驗證範圍，需要實測或引用文獻；`mu_safety` 的上限可能限制旋轉。
- G1 手腕力矩（5 N·m）和速度限制可能不夠打出高轉速。
- 硬體：左手托球板、真實的球拍安裝方式（g1-port 目前的球拍安裝是假設值）。
- 放球改拋球（合法化）：左手要做往上拋的動作，時間點也要跟著變。
