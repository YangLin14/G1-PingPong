# 其他人形機器人桌球系統：哪些值得我們試（2026-10-19）

[English](humanoid_table_tennis.md) · [文件目錄](../README.zh-TW.md)

調查 SMASH（港大，2026 世界人形機器人運動會銀牌）、北大－智源隊（同一屆金牌），以及相關的 HITTER（我們的基礎配方）和 PACE，
重點在平衡和穩定回球。數字都照來源寫；「實機」= 在真的機器人上量的。

## 各系統簡介

| | SMASH（港大） | 北大－智源 | HITTER（柏克萊） | PACE（普渡） |
|---|---|---|---|---|
| 機器人 | Unitree G1 | 比賽用智元 A3（所有隊伍都用 A3）；論文是 6 軸 ABB 手臂 | Unitree G1，29 自由度 | Booster T1 |
| 控制 | 模型規劃器 → PPO 全身追蹤動捕 clip（400 個真的 + 5000 個生成的），手腕不追蹤 | 人形的方法沒公開；手臂論文：物理預測 + 學出來的修正量 + 以落點區域為條件的模仿策略 | 規劃器給球拍目標**和底座 xy 目標**；PPO | 一個端到端 RL 策略（揮拍 + 步伐） |
| 腳 | 可以左右移動 | 沒公開 | 實機上每次移動**只踏一步**（用速度指令時會踏好幾步） | 學出步伐 |
| 平衡 | 沒有專門的平衡獎勵；推擠 + 摩擦隨機化；實機擊球後 20/20 都站穩 | 沒公開 | 沒寫 | 跌倒就結束 |
| 回球 | 實機：動捕 18/20，頭部相機 12/20；642 球中 59.7% | 手臂實機：92% 落在目標 30 cm 內 | 實機：回球 92%，最長對打 106 拍 | 實機：回球 61% |

來源：SMASH arXiv 2604.01158（https://mmlab.hk/Smash/）；SpikePingpong arXiv 2506.06690（北大）；
WHRG 2026 報導（新華社、北大新聞）；HITTER arXiv 2508.21043；PACE arXiv 2509.21690。
沒有一個系統把腳固定；也沒有人用 ZMP/重心硬限制。

## 值得我們試的（依價值排序）

1. **訓練和部署在擊球後給一樣的指令；移動時踏一步就好，不要碎步。** HITTER（真 G1）用底座目標指令做到每次只踏一步。
   **今天已經做了：** 我們的部署在擊球後給了錯的目標；`hold_last_target` 讓 MuJoCo 裡的踏步完全消失（每球 3.5 步 → 0 步）。
   下一步：腳的接觸改變懲罰，只在底座目標很遠時才關掉（D22 的三個訓練測試兩個極端：固定站位、腳完全不動）。
2. **離擊球越近越小的指令雜訊**（SMASH 式 14）：在目標位置、速度、時間上加雜訊，離擊球遠時大、近時小。
   真 G1：有這個回球 13/20，沒有只有 7/20。工作量小。我們的 `vb_timing_jitter_s` 只有時間雜訊。
3. **從根本修好打短的問題。** (a) 重新擬合恢復係數和空氣阻力，讓規劃器預測的出球跟球拍實際打出的一致（HITTER 用 15 顆錄下來的球擬合）；
   固定打短（我們的瞄準補償 +0.23 m）通常表示恢復係數或實際揮拍速度有偏差。(b) PACE 式獎勵：擊球後預測的落點和過網高度。
   (c) 之後在實機上：像 SpikePingpong 一樣，用記錄下來的（指令 → 落點）學一個球拍目標的修正量（手臂：30 cm 內 23% → 92%）。
4. **自動縮小追蹤標準差 + 依區域加權取樣**（SMASH，只有模擬）：誤差變小時就縮小球拍獎勵的 std（沒有的話他們模擬成功率 86% → 23%）；
   成功率最低的區域/來球多取樣。
5. **手腕不做模仿；拍面獎勵不分正反面**（SMASH）：讓策略自己調拍面（= 出球方向），又不會破壞身體動作。
6. **為實機加強隨機化**：PACE 從模擬 94% 掉到實機 61%，原因是腳踝機構和馬達動態；G1 的腳踝也是並聯連桿。
7. **更多正手 clip**（SMASH：400 → 5000 個 clip，模擬成功率 77% → 86%）。工作量大。

目前不建議：ZMP/重心硬限制（沒有系統用）。完全不准踏步沒有證據支持，可能讓抗推能力變差；D22 的第 3 個訓練就是在量這件事。
